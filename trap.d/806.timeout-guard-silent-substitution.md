While self-reviewing #806's fix (a configurable `thresholds.consolidate_timeout_seconds` for the
staging -> recent/archive consolidation path, mirroring #788/#792's `thresholds.ndc_timeout_seconds`
for the sibling NDC now.md path), the auditor spawn flagged: the new digit-only guard in
`scripts/run-consolidation.sh` --

```
CONSOLIDATE_TIMEOUT_SECONDS=$(config ".thresholds.consolidate_timeout_seconds" 180)
case "$CONSOLIDATE_TIMEOUT_SECONDS" in ''|*[!0-9]*) CONSOLIDATE_TIMEOUT_SECONDS=180 ;; esac
```

-- silently substitutes the default 180 whenever the configured value is empty or contains a
non-digit, with no `log`/`report_error` call anywhere near it. An operator who typo'd the config
key's value (e.g. `"18O"`, a stray comment, a `jq` error string) sees exactly the same behaviour --
silent default 180 -- as one who deliberately configured 180, with nothing in the daily log
distinguishing "I read your value" from "your value didn't parse and I ignored it."

Not new to this diff: it is byte-for-byte the same shape as the already-shipped sibling guard in
`scripts/save-session.sh:1149-1150` for `thresholds.ndc_timeout_seconds` (#788/#792), and neither
guard's fallback branch has any test at any level -- `tests/test_ndc_reject_gate.py`'s
`TestNdcTimeoutIsConfigurable` only exercises a valid numeric override, never a malformed one, and
this diff's own new tests only reach `consolidate()`/`cmd_consolidate()`/`main()` directly at the
Python-argv level, never through `scripts/run-consolidation.sh` itself -- so nothing in the suite
would notice if either `case` line were deleted entirely.

Ranking (per skills/manager/phases/findings.md): closest row is `misreports` -- a value is silently
substituted without reporting the substitution -- non-blocking, not a release blocker. Considered
`fails-to-preserve` and rejected it: nothing is lost, staging is untouched either way, only the
operator's ability to tell configured-180 from garbage-defaulted-180 is lost.

Where: `scripts/run-consolidation.sh:137-138` (this diff's new guard) and, identically,
`scripts/save-session.sh:1149-1150` (the pre-existing sibling guard it copies the shape of) -- a
fix to one without the other would leave the inconsistency it exists to close.

What would settle it: a `log "consolidation"`/`log "ndc"` line (or a `report_error()` call, matching
the pattern `staging_warn_bytes` already uses) on the fallback branch of both guards, naming the
malformed value it discarded, plus a regression test that sets a malformed
`thresholds.*_timeout_seconds` and asserts the daily log records the substitution -- something
neither `test_ndc_reject_gate.py` nor this diff's own tests currently do.

Not decided here: whether this becomes a rule, or is filed as an issue once someone picks it up to
fix, or whether the two guards should share one shell helper function instead of two independent
copies -- a promotion-pass decision, not this one.
