#799 self-review (both spawned reviewers -- Explore and oss:auditor -- converged
independently on this) surfaced a second, non-blocking finding not fixed in this
lane's commit: the new test class in
tests/test_write_handoff_tracked_target_750.py inherits that file's existing
module-level `pytest.mark.skipif(sys.platform == "win32", reason="bash subprocess
+ POSIX write-handoff script -- not portable to Windows runners (#79)")`, copied
verbatim from the sibling file tests/test_injection_guard_ancestor_symlink.py.

This repo already has an in-tree finding that this exact reason is stale for a
"bash subprocess" shape: tests/test_session_end_log_names_488.py's own comment
(lines ~47-57) documents that a blanket `skipif(sys.platform == "win32")` makes
the windows-latest CI leg collect these tests, skip every one, and report the
leg green -- a check that never ran rendering exactly like a check that found
nothing -- and that tests/test_hooks_json.py already proves a real bash IS
reachable under Git Bash on that same leg. That file narrows its own skip to
`BASH is None` via `_bash_runner.resolve_bash()` instead of blanket-skipping on
platform name.

For write-handoff.sh's own symlink test specifically, the auditor reasoned
(not observed) that the actual constraint is more likely `.symlink_to()` itself
needing elevated privilege/Developer Mode on native Windows even under Git Bash
-- a fact the "not portable to Windows runners" reason never names, and which
may or may not be true (not verified against an actual windows-latest run).

Not fixed in #799's own commit: narrowing the skip touches two files (this one
and its sibling, which the #799 diff never otherwise touches) and needs
deciding whether the same `_bash_runner.resolve_bash()` narrowing applies, or
whether the real constraint is symlink privilege and needs a different guard
entirely (e.g. attempt a real symlink creation in a tmp dir and skip only on
actual failure). Left as unresolved-verdict, worth curating into either a
jit-context rule ("a blanket win32 skipif reads suspicious in this repo,
narrow to the actual missing capability") or a tracked issue to retrofit both
existing files plus this new one.
