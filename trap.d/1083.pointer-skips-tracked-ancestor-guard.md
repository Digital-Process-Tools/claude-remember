#1083: pointer-store route skips the #750/#799 tracked/symlinked-ancestor write refusal

What was observed: release-auditor gate-3 round 1 (dispatch token 7cf3acd0c77ea2f3) on the
v0.44.1..HEAD delta found a composition defect between two otherwise-clean commits. #1083
(commit 0e6888f) adds a SessionStart-pointer route in scripts/write-handoff.sh: when
_WH_POINTER_DIR is set, the ancestor walk that derives CLAUDE_PROJECT_DIR is skipped
(write-handoff.sh:148), so CLAUDE_PROJECT_DIR stays at the git toplevel while
REMEMBER_DIR is overwritten from the pointer (write-handoff.sh:204-207).
MEMORY_PROJECT_DIR/PROJECT_DIR are not updated to match.

Where: scripts/write-handoff.sh, the tracked/symlinked-ancestor refusal at lines 337-363,
which only fires when "$_WH_REMEMBER_ROOT" = "$_WH_MEM_PROJ". In the canonical #776
shape (a legacy .remember store tracked inside a repo subdirectory A, with git root R),
the pointer route leaves the root at A and the project guess at R, so the refusal is
silently skipped. At v0.44.1 (before #1083) the hint check set CLAUDE_PROJECT_DIR=A, so
the guard ran correctly. A second site with the same root cause: scripts/doctor.sh
(--json, lines 238-253) computes storage_mode from the pointer REMEMBER_DIR against the
cwd-guessed PROJECT_DIR, and can report "external" for a legacy store.

What it cost: a full gate-3 release-audit round (round 1 of the v0.44.1->0.45.0 release),
which this finding alone sent back for a second round since round-one findings always stop
the tag.

How it was confirmed: reasoned from reading write-handoff.sh and doctor.sh; not exercised.
A reproduction is named but not run: create git repo R with tracked subdirectory
A/.remember/remember.md, write a SessionStart pointer for session S naming A/.remember,
then run CLAUDE_CODE_SESSION_ID=S scripts/write-handoff.sh from R with CLAUDE_PROJECT_DIR
unset. Expected (per the auditor reading): exits 0 with "Wrote handoff to"; at v0.44.1 the
same shape exits 1 with "REFUSED: ... tracked". None of tests/test_session_store_pointer_1083.py
combines a pointer with a git-tracked or symlinked target.

Ranking table row: misreports (non-blocking, can ship behind a trap.d fragment). Fix
direction per the auditor: derive the in-project test (_WH_MEM_PROJ) from the pointer own
store, not from the cwd-guessed project root.


Round 2 update (dispatch token a69f445acec9e55b): re-derived independently and reproduced
with a control, not merely reasoned.

Reproduction run: scratch repo R with a tracked file A/.remember/remember.md.
- No pointer, CLAUDE_PROJECT_DIR=R/A: write-handoff.sh printed
  "REFUSED: .../R/A/.remember/remember.md is tracked by this repository's own git index...",
  rc=1 -- the guard fires correctly here.
- Pointer naming R/A/.remember, CLAUDE_PROJECT_DIR unset, cwd=R/A: printed
  "Wrote handoff to: .../R/A/.remember/remember.md", rc=0, and the tracked file's content
  changed. No cd elsewhere is needed -- cwd sitting in the subdirectory project's own
  directory is enough, which makes this the ordinary #776 subdirectory-project shape, not
  an edge case.
- Same pair with R/B/.remember as a symlink to a directory outside the repo: refused
  without the pointer; with the pointer it printed "Wrote handoff to..." and remember.md
  was written into the symlink's target, outside the store. The symlinked-ancestor branch
  is bypassed too, not only the tracked one.

Correction to the doctor.sh claim above: in the plain subdirectory setup, doctor.sh:248
correctly reports storage_mode=legacy (R/A/.remember sits under R). The doctor.sh --json
storage_mode second site only misreports external when the cwd-guessed project does NOT
contain the pointer's store (e.g. a sibling directory) -- that part is still reasoned, not run.

Ranking row confirmed as misreports (non-blocking) by both rounds. Considered and rejected:
containment (write) (the target is not an argument slot -- it comes from SessionStart's own
pointer) and containment (read) (a path chokepoint would only fix the symlink branch, not
the tracked-file branch). If a maintainer later reads the symlink branch as containment
instead, the row becomes blocking -- that is the one fact that would change this.

Open observation, not a finding: save-session.sh:947 (#1052, 55978fa) adds
mkdir -p "${REMEMBER_DIR}/tmp" with no REMEMBER_DIR_UNSAFE check, after #920 (825b482)
gated the other mkdir sites. Reasoned but not traced far enough to confirm whether it is
reachable on an unsafe REMEMBER_DIR (it sits behind save.lock acquisition, which may itself
require $REMEMBER_DIR/tmp to exist).

Fix direction unchanged: derive the in-project test (_WH_MEM_PROJ) from the pointer's own
store, not from the cwd-guessed project root. A test combining a pointer with a git-tracked
or symlinked target (tests/test_session_store_pointer_1083.py has none) would settle it
going forward.
