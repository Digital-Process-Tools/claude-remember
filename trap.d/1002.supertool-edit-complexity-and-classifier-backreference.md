Observed during the #1002 lane (Windows hidden-detach launcher fix).

A supertool edit/paste payload containing the two words naming a popular shell distribution for
Windows (as in "X Bash"), or shell code with a command substitution written inline inside a case
pattern arm, tripped the harness's own Bash-tool complexity refusal for a reason unrelated to its
stated concern. Rewording the prose and moving the substitution onto its own line fixed both, with
no change in meaning.

Separately, review_return.py's --framed back-reference heuristic classified a reviewer's message
as referred-not-stated even though every claimed finding was fully stated in the body, because a
trailing one-line recap sentence ("findings stated inline above") was read as pointing outside the
message rather than at the same message's own earlier paragraphs. The genuine failure mode this
tool exists to catch and this false-positive produce the identical output line, and nothing in it
tells the two apart -- confirming which applies cost one full re-read of the message by hand.
