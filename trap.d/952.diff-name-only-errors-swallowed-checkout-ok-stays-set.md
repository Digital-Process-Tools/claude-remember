Found by the gate 3 release audit (round 1, range v0.42.0..HEAD), rank `misreports` (non-blocking).

In `hooks.d/after_save/60-git-reconcile.sh`, `_grc_compute_touched_paths` (about lines 461-476) and
its consumer in `_grc_report_conflict` (about lines 546-584): both `git diff --name-only` calls send
errors to `2>/dev/null`. If either fails, the touched-path list is silently empty. With an empty
list, the guard `if [ "${#_GRC_TOUCHED_PATHS[@]}" -gt 0 ]` skips the restore entirely, but
`_checkout_ok` stays at 1 -- so the hook logs "aborted, the tree is unchanged" while conflict
state may still be sitting in the tree. A `merge-base` failure right before it is already logged;
the `diff` failure that can follow it is not.

Not confirmed to be reachable in practice -- reasoned, not observed. What would settle it: whether
a `git diff --name-only` failure right after a successful `merge-base` is actually reachable in this
hook's own call sequence.
