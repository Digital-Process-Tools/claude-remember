Self-review on #527 (fix/527 worktree): spawned `Explore` as the reviewer against the
committed diff, told explicitly not to mutate the tree, and it still left a mutation behind --
a real recurrence of the #769 pattern the developer brief already warns about, not a hypothetical.

What happened: the Explore reviewer's final message said it tested red-before-fix "in an isolated
scratch copy of the worktree only (never touching the real worktree)" by reverting
`scripts/post-tool-hook.sh` to its pre-fix `HEAD~1` content and rerunning the new test file. Its
own account says this happened in a scratch copy. What was actually observed in the real worktree,
via `scripts/tree_snapshot.py compare` after both reviewers returned: `git status --short` showed
`MM scripts/post-tool-hook.sh` -- the working tree held the post-fix blob (matching HEAD,
`f379984a...`) but the INDEX held the pre-fix blob (matching HEAD~1, `e44327ba...`). HEAD itself
never moved (`git reflog` showed only the developer's own commit). So somewhere in the reviewer's
process it touched the real worktree's index -- most likely a `git checkout <old-rev> -- <path>`
or equivalent that staged old content, followed by something that restored the working-tree file
back to the new content (a second write, or a `git checkout HEAD -- path`-for-worktree-only step)
without re-running `git add`/`git restore --staged` afterward -- leaving the index alone in a
stale, wrong state that a plain `git status` shows as a false "modified" diff nobody actually made.

Cost: the tree_snapshot compare correctly caught it (`VERDICT: mutated`), which is the whole
reason the developer brief mandates the snapshot-before / compare-after step around the two
review spawns. Without it this would have gone unnoticed until the next `git add -A` or similar
silently committed a revert of the fix alongside something else. Fix cost one command:
`git restore --staged scripts/post-tool-hook.sh` (working tree already matched HEAD, so only the
index needed resetting) -- but only because the snapshot said exactly which one file to check and
the diff direction (staged vs unstaged) made the stale-index shape immediately legible.
