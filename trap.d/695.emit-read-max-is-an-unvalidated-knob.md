# `REMEMBER_EMIT_READ_MAX` is the one unvalidated numeric read in lib-memory-context.sh

`scripts/lib-memory-context.sh` reads `${REMEMBER_EMIT_READ_MAX:-16384}` and uses it
directly in `[ "$2" -gt "$_remember_emit_max" ]` with no `case (''|*[!0-9]*)` guard —
while `MEMORY_INJECT_MAX_BYTES`, `log.sh`'s `_budget`/`_grace`, and every `wc` parse in
the same file all carry one.

Observed under `set -eu` with a non-numeric value: bash prints
`[: notanumber: integer expression expected` to stderr, does **not** abort (the test is
an `if` condition, so `set -e` is suppressed), and falls through to the `read` arm —
sending every file down the quadratic path the 16 KB threshold exists to keep them off.
The same failure #695's round-1 repair fixed from the other direction.

Found by the v0.33.0 release audit, round 2 (`rel-0330-r2-96ee92d0`), ranked `misreports`.
Low weight because it is self-inflicted: an undocumented env knob set to nonsense.

Two honest fixes: guard it like its neighbours, or state in the comment that it is not
user-settable. What settles which: whether the knob is meant to be set by anyone at all.
