Auditor finding from the #719/#723 self-review (Class A, "an absence the
caller cannot read"), argued down to non-blocking and logged here rather
than fixed in that lane, per the findings table's "can ship behind a
trap.d fragment" row.

In `hooks.d/after_save/50-git-backup.sh`, the block that writes the
`/$SLUG/config.json` (and logs/tmp) exclusion rules into
`$GIT_COMMON_DIR/info/exclude` is gated by:

    if [ -n "$BACKUP_COMMON_DIR" ] && mkdir -p "$BACKUP_COMMON_DIR/info" 2>/dev/null; then
        ...
    fi

with no `else`. Every other failure path in this file (commit failure, push
rejection, untrack failure) logs a WARNING/ERROR; if `mkdir -p` fails here
(read-only filesystem, permission issue, `BACKUP_COMMON_DIR` empty), the
exclusion is silently never written, and the subsequent `git add -- "$SLUG/"`
stages `config.json` exactly as before the #719 fix -- the caller sees the
ordinary "committed $SLUG" success line, indistinguishable from the
exclusion having worked.

This is inherited code shape: the identical guard, with the identical
missing `else`, already existed before #719 for the logs/tmp exclusion --
this diff only added `config.json` to the same `for` loop inside the
existing `if`, it did not introduce the silent-failure shape. What changed
is the stakes: the guard now silently gates protection of a live OAuth
credential rather than just housekeeping files, which is why the auditor
flagged it now rather than it being new.

Not fixed in the #719/#723 lane because: the failure mode is unchanged
behavior inherited from pre-existing code, the blast radius of adding a
proper `else` branch (an `else` clause, a `report_error` call, and a test
for a `mkdir -p` failure -- which needs a way to make `mkdir -p` fail in a
test fixture, e.g. a read-only `$GIT_COMMON_DIR` on POSIX) is not "one
sentence", and it touches the same `if` this diff's own `config.json`
exclusion depends on -- widening it felt like it belonged in its own
reviewed change rather than riding along on two already-committed fixes.

For whoever curates this: candidate shape for the fix is an `else` branch
next to the existing `if`, e.g.

    else
        report_error "git-backup" "WARNING: could not create $BACKUP_COMMON_DIR/info -- the logs/tmp/config.json exclusion was NOT written, so this backup's git add may stage config.json (which can carry haiku.oauth_token)."
    fi

paired with a test that makes `mkdir -p "$BACKUP_COMMON_DIR/info"` fail
(e.g. by pre-creating a file at that path, or chmod-ing the parent
read-only) and asserting the WARNING appears and/or config.json is still
excluded some other way.
