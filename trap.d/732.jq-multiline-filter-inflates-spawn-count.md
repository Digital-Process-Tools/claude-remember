Investigating a macOS-only CI failure on PR #732 (branch fix/722): CI's 3
macOS legs (macos-latest, py 3.9/3.10/3.11) failed deterministically on
tests/test_post_tool_hook_spawns.py::test_the_post_tool_hook_stays_inside_its_spawn_budget
(observed 20 spawns against POST_TOOL_SPAWN_BUDGET=19), while the other 12
legs (ubuntu, windows) were green and origin/main was green 14/14 on the
same matrix.

Root cause: not a real extra process fork. scripts/lib-memory-dir.sh's #726
change wrote its new jq merge filter as a multi-line quoted string:

    jq -s --argjson strip_last_haiku "$_strip_project_haiku" '
        (if $strip_last_haiku then ... else . end)
        | reduce .[] as $x ({}; . * $x)
        | with_entries(...)
    ' "${_cfg_sources[@]}" > "$_merged_cfg" ...

This is ONE shell command / one jq process, exactly as before #726. But
tests/spawn_counting.py's shim logs every spawn as
`printf "%s %s\n" "$name" "$*"`, and `"$*"` faithfully includes any literal
newline characters embedded in an argv value (bash single-quotes preserve
them literally). Because the jq filter argument now spans 4 embedded
newlines, ONE process writes 5 physical lines to the spawn log instead of
1. `spawns()` (tests/spawn_counting.py) splits the log on newlines and
counts non-blank lines, so it counted this single process as 5 "spawns" --
a phantom +4.

Why only macOS failed: origin/main's macOS-bash-3.2 warm-run measurement
was 16 (budget 19, 3 slack). The +4 phantom pushed it to 20 (>19, fail).
On ubuntu/windows (bash >= 4.2), a *different*, unrelated saving
(`_remember_date`'s builtin fast path, no `date` fork) already left enough
slack that +4 phantom lines still landed under budget -- coincidentally
masking the same miscount on those legs. The maintainer's own local macOS
run also didn't reproduce it, because their local `bash` on PATH resolved
to a homebrew/GNU bash >= 4.2, not the CI runner's stock
/bin/bash 3.2 -- reproducing this locally required explicitly prefixing
PATH with `/bin` (ahead of homebrew) so `bash` resolved to the system
3.2.57 binary. Confirmed by A/B swapping scripts/lib-memory-dir.sh between
this branch's content and `git show origin/main:...` in place (then
restoring and verifying `git status` was clean before/after) and re-running
the same test under that PATH.

Lesson for whoever writes a jq/awk/sed filter as a shell heredoc-like
multi-line quoted string in this repo: if ANY test anywhere counts spawns
by splitting a recorded `"$*"` log on newlines (tests/spawn_counting.py's
`spawns()` is the one shared implementation, used by at least a dozen
files), a multi-line quoted argument silently inflates every count that
includes that call, by (embedded-newline-count) minus zero -- with no
real behavior change and no signal at the point the multi-line string is
written. jq itself is whitespace-insensitive, so collapsing the filter to
one line is a pure fix with no functional change. Fix applied: collapsed
the filter back to a single line (fix/722, same commit as this fragment).
