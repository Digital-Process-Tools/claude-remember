Release audit (v0.39.0, round 1, oss:release-auditor) found that #894's docs sweep did not
reach every file telling users to set the now-removed `REMEMBER_OAUTH_TOKEN` env var.

`docs/diagnostics.md:16` (added by 6f32952/#870) tells users with an auth failure to set
`REMEMBER_OAUTH_TOKEN` via `claude setup-token`. Three commits later, e0cbc3c/#894 removed
that variable as an auth source entirely (`pipeline/haiku.py:_configured_oauth_token` now
reads only `CLAUDE_PLUGIN_OPTION_OAUTH_TOKEN`). Neither diff by itself contains the defect --
it is a composition gap across two otherwise-clean PRs.

The same stale advice survives in files #894's sweep did not touch:

- docs/git-backup-security.md:55 ("prefer the `REMEMBER_OAUTH_TOKEN` environment variable")
- docs/external-storage-mode.md:73
- docs/configuration.md:59 and :71
- docs/verification.md:16

A user who follows these docs sets a variable that is no longer read, and stays
unauthenticated until doctor's NOTICE section flags it (see the sibling fragment on that
section's own staleness, 894.doctor-notice-grep-is-history-not-presence.md).

Ranked `misreports` (non-blocking) against skills/manager/phases/findings.md's table.
What would settle it: a `git grep REMEMBER_OAUTH_TOKEN -- docs` sweep, keeping only lines
that mark it as removed.
