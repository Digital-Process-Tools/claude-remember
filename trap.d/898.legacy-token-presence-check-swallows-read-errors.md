Observed during #898 round-3 self-review (oss:auditor pass): `pipeline/haiku.py`'s
`_legacy_recovery_token_configured()` (the function behind the "still-set legacy
recovery-token setting" NOTICE) has `except (OSError, ValueError): continue` around each
config-candidate read. A config.json that is genuinely unreadable (permission denied) or
malformed (invalid JSON) silently falls through to the same `False` return as "nothing is
configured there" -- so the NOTICE this function drives cannot distinguish "nothing to
migrate" from "couldn't tell." This is not new in round 3: `git show 8484fec:pipeline/haiku.py`
shows the identical shape already present in round 2's `_legacy_config_key_present`, before
the two legacy-presence checks were merged into one function this round. Not fixed here:
ranked `misreports`/non-blocking against `skills/manager/phases/findings.md`'s table, and
distinguishing the two outcomes would need the return type to carry a third state rather than
a bare bool, which is a larger, separable change than this round's scope.
