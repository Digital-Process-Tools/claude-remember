Self-review on #946 (foreign-rebase decline guard) surfaced, via the `oss:auditor` spawn, that
`_grc_rebase_in_progress` (hooks.d/after_save/60-git-reconcile.sh:353-371, unchanged by this fix)
returns a plain false ("not in progress") both when `.git/rebase-merge`/`rebase-apply` genuinely
does not exist AND when the underlying `git rev-parse --path-format=absolute --git-path ...` call
itself fails for some unrelated reason (e.g. git binary trouble, a corrupt .git directory read
error) -- a "could not tell" collapsed into "nothing there".

The auditor traced the consequence for both of #946's new pre-check call sites and found it
non-destructive: a false negative at either new pre-check only lets the hook go on to attempt its
own `git rebase`, which then either succeeds or fails for the same underlying reason, landing in
the harmless "WARNING ... failed to start ... no-op" branch rather than ever reaching the
destructive `rebase --quit` + scoped-checkout branch (that branch is only reached when the SAME
function returns true, at the pre-existing post-check around line 581, after the hook's own
rebase call has already failed). So the worst observed consequence today is a misleading log line
("declined" vs. "failed to start"), not data loss.

Ranked `misreports` (non-blocking) against the findings table, and logged here rather than filed,
per that table's "can ship behind a trap.d fragment" row -- not unique to #946's own new call
sites; it is a property of the pre-existing, unchanged function that every one of its four call
sites (353/490/569/581, plus #946's new 527/554) inherits alike.

What would settle it: distinguishing "directory does not exist" (git-path call succeeded, `-d`
test false) from "could not determine" (the git-path call itself failed, non-zero exit) inside
`_grc_rebase_in_progress`, and deciding -- as a design question, not a mechanical one -- whether
the undetermined case should behave like "in progress" (safer default: decline/report rather than
proceed) or surface its own distinct log line, worth the curator's attention as a class across all
call sites rather than a one-off patch to #946's two new ones.
