In `hooks.d/after_save/60-git-reconcile.sh`, about lines 473-474, 571 and 584: the touched paths
come from `git diff --name-only` with git's default path quoting (`core.quotePath`) left on. Any
path with non-ASCII or special bytes comes back as a quoted string, and nothing un-quotes it before
it is passed back to `ls-tree`, `checkout`, `diff` and `rm`. That path matches nothing and silently
drops out of the restore, while `_checkout_ok` can stay 1 and the "tree is unchanged" message still
prints. Before #952 the restore named only `$SLUG` (from `session_dir_slug`, which does not have
this problem); now it reaches any path in the store's repository, which can be a user-chosen git
repo when `data_dir` is set.

CI coverage: not covered. `.github/workflows/tests.yml` runs ubuntu/macos/windows across Python
3.9-3.12, but the defect is not platform-specific and no fixture uses a non-ASCII path. What would
settle it: whether the store root can hold non-ASCII tracked paths in a supported layout.
