# The divergence-fold pattern replaces `old_code`, it does not extend `new_code`

**Observed:** working #761 against `tests/test_case_divergence_298.py`'s
`_SANCTIONED_DIVERGENCE` allowlist (a byte-pin guard for
`scripts/lib-memory-dir.sh` against `origin/main`), my first attempt at
folding the #761 change into the existing #766/#757 pair edited only the
`new_code` half of the tuple in place -- extending it with the #761 addition
while leaving `old_code` as it was. That broke the guard:
"neither the old nor the new code of this sanctioned substitution is on
origin/main".

**Why:** the fold pattern (established at #734/#746, a comment in the same
file names the precedent) is: what was previously `new_code` -- since shipped
and now live on `origin/main` -- becomes the new `old_code`, and `new_code` is
extended to include the newest change on top of that. Editing `new_code`
alone leaves `old_code` pinned to a form that predates the last fold and is
no longer on `origin/main` at all, so the guard can match neither entry.

**Cost:** roughly 3 extra read/edit cycles to diagnose (re-reading the guard's
own failure message, diffing `old_code` against `git show origin/main:...`
by hand, then realizing the whole `old_code` element needed replacing, not
just extending `new_code`) and correct.

**How confirmed:** replaced `old_code` with the byte-for-byte text of
`scripts/lib-memory-dir.sh` as it stands on `origin/main` (verified via
`git show origin/main:scripts/lib-memory-dir.sh`), then extended `new_code`
with the #761 addition on top of that. Guard passed after the correction.

**For a future lane touching this same guard file:** before editing either
half of a `_SANCTIONED_DIVERGENCE` tuple, check whether the existing
`new_code` half is already what `origin/main` currently ships -- if so, that
whole half moves to `old_code` verbatim, and only then does `new_code` grow
the newest diff on top of it. Do not extend `new_code` in place while leaving
a stale `old_code` behind.

Unsure whether this graduates into anything more automated (e.g. a
self-check in the test file that fails earlier with a more specific message)
-- flagged here for a later promotion pass rather than decided now.
