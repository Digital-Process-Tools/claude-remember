Release audit for v0.42.3 (round 2, gate 3) flagged scripts/lib-detach.sh:100-121
together with scripts/windows-hidden-run.vbs:54-61.

What was observed: lib-detach.sh builds
`c_script='exec bash "$0" "$@" >>'"$outfile_q"' 2>&1'`, which contains literal
double quotes, and passes it as one argv entry to `wscript.exe`. Windows Script
Host's own argument parser removes double quotes and does not honour `\"`
escapes, so `WScript.Arguments` cannot carry a literal `"`. Reasoned, not
observed: on a real Windows host the `-c` script reaching bash is therefore not
the one lib-detach wrote -- `$0`/`$@` get mangled into one literal word or
split, `exec` fails, and the save never runs. Meanwhile `_remember_detach_windows`
has already returned 0, so post-tool-hook.sh:1064 skips its nohup fallback --
every PostToolUse background save silently skipped on a stock Windows host
where wscript.exe is present and healthy.

Why CI misses it: the hidden-route tests in
tests/test_windows_hidden_detach_1002.py swap in a stub `wscript.exe` written
in bash, so the real WScript.Arguments parser never runs. The VBS's
output-side `QuoteArg` is pinned against `list2cmdline`
(tests/test_windows_hidden_detach_1002.py:484), which checks the output side
only -- nothing tests the input side (the quotes inside `c_script` itself
surviving the wscript.exe argv hop).

How this differs from the round-1 fragment
(trap.d/1002.detach-windows-silent-skip-after-launch.md): that one covers WSH
being disabled or removed entirely. This is a deterministic argument-encoding
fault on a *healthy* WSH, and needs a different fix: pass the outfile/wrapper
so the `-c` script needs no embedded quotes, or test the round trip through
real WScript.Arguments rather than a stub.

What would settle it: on a Windows host, have windows-hidden-run.vbs echo
`WScript.Arguments.Item(2)` and compare it byte-for-byte with lib-detach's own
`c_script` value.

Ranked `fails-to-preserve`, non-blocking per the release-3 ranking table --
logged here rather than filed, for /oss:curate to triage.

Round 2 update (branch fix/1002-real-wscript-evidence): the embedded-quote
argv entry this fragment describes has been removed entirely rather than
settled by observation -- OUTFILE is now its own separate WScript.Arguments
entry and lib-detach-pidwrap.sh does its own redirect, so no argument on
the wscript.exe call carries a literal quote any more. Real-wscript.exe CI
evidence for the fix (tests/test_windows_real_wscript_1002.py, including a
path-with-a-space case) is pending on this branch's own windows-latest CI
run; this fragment stays open until that result is recorded here.
