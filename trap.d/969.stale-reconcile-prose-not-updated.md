Self-review (Explore spawn) on the #969 kill-switch diff found that hard-disabling
`hooks.d/after_save/60-git-reconcile.sh` left two files describing the OLD, now-false
behavior untouched:

- `hooks.d/after_save/50-git-backup.sh` (around lines 505 and 519): when
  `git_reconcile.enabled=true` and a push is rejected, the log line and the
  `git-backup-notice` both still say "git_reconcile.enabled is on, so the next
  after_save run (60-git-reconcile.sh) may fetch, rebase and push this
  automatically" -- this is now false; the hook exits before reading that flag
  at all.
- `scripts/user-prompt-hook.sh` (around lines 367-369, 375-379): the notice
  routing-table comments make the identical now-false claim, but only as
  internal documentation (not user-facing text), so lower impact.

Why this was not fixed in the same diff: `50-git-backup.sh`'s wording is under a
protected, named test contract --
`tests/test_git_backup_push_rejected_253.py::TestTheRejectionNoticeRespectsReconcile`
(from #935) -- with three tests asserting specific substrings ("fetch, merge or
rebase" present/absent, "git_reconcile" present/absent) keyed to the CURRENT
(pre-#969) behavior where reconcile really does act automatically when enabled.
Correcting the prose to describe the new hard-disabled reality means rewriting
that test class's assertions too (it would need to say nothing will happen
regardless of the flag, the same shape as the already-disabled case), which
is a second file + a second test file's protected contract -- past the
"blast radius is one sentence" bar for a same-diff fix, and a decision
(does #935's distinction between enabled/disabled collapse entirely while
#969 is open, or does the wording just get a "currently inert" caveat?)
better made with full context on #969's own real fix, not mid-kill-switch.

Also worth noting for whoever works this: the reverse of the #935 bug has now
shipped -- #935 fixed "the log falsely promises nothing will auto-resolve when
reconcile actually will"; this trap is "the log falsely promises something will
auto-resolve when reconcile (temporarily) never will." Same notice, same two
knobs, opposite direction, now both wrong at different times depending on
whether #969's kill switch is still in place.
