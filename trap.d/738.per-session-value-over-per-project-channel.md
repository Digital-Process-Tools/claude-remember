#738: a per-SESSION value carried over a per-PROJECT channel.

`session-start-hook.sh` resolved a per-session handoff target
(`remember.<session_id>.md`, only in `handoff_mode: "per_session"`) and
published it to `$REMEMBER_DIR/tmp/handoff-path` -- a single file, written on
EVERY SessionStart, regardless of which session started it. `write-handoff.sh`
then trusted that one file with no idea which session was actually calling
it. The bug wasn't in either resolution step -- the per-session path was
computed correctly, the shared file was written correctly -- it was that a
value whose correctness depends on WHICH SESSION is asking was handed off
through a channel that has no notion of "which session" at all: one path,
last writer wins, readable by anyone. Two sessions running concurrently
(the ordinary case for `per_session` mode, not an edge one -- see #363) is
enough to make the LAST session to start own the pointer, so an EARLIER
session's later `/remember` silently wrote into a DIFFERENT session's file.

The general shape, worth watching for elsewhere in this codebase: a value
computed per-request/per-session/per-caller, published through a fixed,
shared location for a downstream reader to pick up later out-of-band. The
value itself can be perfectly correct at write time and still be wrong by
the time it's read, because "correct" here is a property of (value, reader)
pairs, and the channel drops the second half. The fix that generalizes: key
the published artifact by whatever identity the shared channel was silently
assuming was unique (here, the session id) rather than trying to make the
channel itself more careful about ordering.

Confirmed by writing the failing reproduction first (two sessions, A then
B, A's later /remember lands in remember.B.md under the old code) and
watching it turn green only once write-handoff.sh started identifying its
OWN session (via CLAUDE_CODE_SESSION_ID, a live env var Claude Code sets
for the Bash tool -- confirmed present by `env | grep CLAUDE` inside this
very session, macOS) and preferring a hint file keyed to that id over the
shared one.

Adjacent, not something this fix touches: `session-start-hook.sh` already
has one working example of this exact pattern done right --
`remember.delivered.<session_id>` (the #373 fix) -- which is why its prune
sweep was the template copied (with a second loop, same GRACE_MIN/#393
coupling) for the new `tmp/handoff-path.<session_id>` files this fix adds,
rather than reasoning the pruning logic out from scratch.
