unlike the shell-side equivalents (`report_error()` / `_dispatch_report_skip()`, which run
`tr '[:cntrl:]' ' '` before writing -- #599/#618).

Found during #870's own self-review: that fix adds a second `_warn()` call site in
`pipeline/haiku.py` that embeds a failure detail string into the same `log()` path, so the
pre-existing gap gets exercised more often by #870's own diff -- but the gap itself predates
#870 and is not introduced by it, so it was left out of that PR's footprint.

Fixing it touches every caller of `log()` repo-wide, which is a different shape of change
than #870's own targeted fix. Confirmed by reading `pipeline/log.py`'s `log()` directly
against the shell-side flattening it lacks; not reproduced with a fresh failing test here
(the #599/#618 pattern already demonstrates the risk class on the shell side).
