#860's DEPRECATED message for the legacy REMEMBER_OAUTH_TOKEN / haiku.oauth_token
fallback (pipeline/haiku.py, _configured_oauth_token()) unconditionally tells the
operator to "configure the recovery token through the plugin's userConfig option
instead (/plugin -> remember -> Configure, or `claude plugin config set remember
oauth_token <token>`)".

That remedy does not exist for a Codex-hosted operator. Codex (.codex-plugin) has
no userConfig mechanism at all -- acknowledged explicitly in this same commit's
docs/releasing.md. But the warning can still fire under Codex: when
REMEMBER_SUMMARIZER_FALLBACK=claude is set and the codex route fails, call_haiku()
falls through to the SAME claude-path code (pipeline/haiku.py's call_haiku, the
`env = _child_env(); env = _inject_configured_oauth_token(env)` lines right after
the codex try/except block) that a native Claude Code host uses. If that Codex
operator has REMEMBER_OAUTH_TOKEN or haiku.oauth_token set (their only recovery
option, since they have no userConfig), every such fallback save now logs a
permanent, unactionable "DEPRECATED ... will be removed in a future release"
nag pointing at a Claude-Code-only remedy.

Found by the Explore self-review reviewer on #860's diff (review finding #2).
Ranked non-blocking (a warning-message UX nit, not a functional regression --
REMEMBER_OAUTH_TOKEN itself keeps working on this path) so it is logged here
rather than filed or fixed in the same diff; fixing it cleanly needs the
deprecation message to know which provider/host is actually running the call
(pipeline/host.py's detect_host(), or threading a "this path has no userConfig
replacement" flag from the codex-fallback branch down into
_configured_oauth_token()), which is more than a one-line change and deserves its
own pass rather than riding along in this diff's blast radius.

Not independently re-verified end-to-end (no real Codex host available in this
environment) -- reasoned from reading call_haiku()'s dispatch logic
(pipeline/haiku.py, provider == "codex" branch falling through to the shared
claude-path code) alongside _configured_oauth_token()'s unconditional _warn()
text, both read directly in this repo.
