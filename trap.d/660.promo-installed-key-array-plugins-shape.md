## installed_key membership check silently reverses on a non-object `.plugins` shape (PR #661)

**What was observed.** PR #661 (`scripts/session-start-hook.sh`, `fix/660`, independent
`oss:auditor` review) replaced a per-candidate, per-key `jq` membership probe against
`installed_plugins.json` with a single `to_entries` probe run once. The old per-key query
(`.plugins[$k] // empty | length`) errors (jq exit 5, "Cannot index array with string") if
`.plugins` is a JSON array rather than an object; that error was caught by a `>/dev/null
2>&1` guard and treated as "cannot tell", which suppressed the promo -- documented inline
as a deliberate #574 review finding. The new single probe calls `to_entries` on `.plugins`
once; `to_entries` is defined for arrays too (producing index keys `"0"`, `"1"`, ...), so it
does **not** error on an array shape. A real `installed_key` like `supertool@dpt-plugins`
never matches an index string, so the membership check now reads "not installed" instead of
"cannot tell" -- the promo **fires** in exactly the situation the old code was written to
suppress it in.

**Where.** `scripts/session-start-hook.sh:1073-1080` (the `to_entries` probe in the rewritten
`_remember_compute_promo()`). Confirmed live: both jq calls run directly against a shimmed
`installed_plugins.json` with `"plugins": ["x", "y"]` -- old path suppresses, new path fires.

**What it cost.** Not caught before merge -- this diff was reviewed after the fact by a
compensating `oss:auditor` audit dispatched by the maintainer tick, because the developer's
own mandatory self-review spawn (`Explore` + `oss:auditor`) could not run at all (`Agent`
tool unavailable inside that nested session, filed separately as
`Digital-Process-Tools/claude-oss#1468`). No test in this diff or the pre-existing
`test_plugin_promo_574.py` exercises a non-object `.plugins` shape.

**How it was confirmed.** Reading both jq calls, reproducing the full bash logic standalone
with a shimmed non-object `.plugins`, and comparing old-path vs new-path behaviour.

**Not decided here.** Whether `installed_plugins.json`'s writer can ever actually emit
`.plugins` as a non-object -- if never, this is latent; ranked `fails-to-preserve`
(non-blocking) rather than blocking because the auditor could not establish it is live. The
fix, if it is live, is a chokepoint in the probe (validate `.plugins` is an object, or catch
a non-object explicitly and fall back to cannot-tell) rather than a data-flow boundary or a
destructive path.
