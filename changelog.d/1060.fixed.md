- Fixed #1060: a host that fires `SessionStart` with `source=resume` on every resumed turn (not just once per session) could pile up background work indefinitely -- one reporter measured 42 stacked processes and host load 275, and a related report measured roughly 700 forced re-saves of the same previous session, each one waiting up to 30 seconds for a lock another copy of itself was holding. Fixed in two parts: (1) a second resume for a session whose background work is still running is now skipped instead of starting a duplicate, via a per-session marker that is correctly treated as stale (and replaced) if the earlier work crashed; (2) the recovery step that re-saves a previous, unsaved session now finishes before the marker is cleared, so a rapid run of resumes for the same session can no longer each kick off their own competing re-save. What this does NOT change: if your tool genuinely runs several sessions in parallel (for example, four concurrent agent workers), each of those sessions still gets its own background work and its own recovery save -- this fix stops ONE session's repeated resumes from piling up, not the number of sessions that may legitimately run at once.
