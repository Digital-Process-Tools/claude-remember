- Fixed #1060: an Agent SDK host firing `SessionStart` with `source=resume` on every resumed turn (not once per session) could stack its backgrounded deferred phase (recovery, capture-gap detection) indefinitely -- one reporter measured 42 concurrent processes and host load 275. A second start for a session whose deferred phase is still alive now skips rather than relaunches, via a stale-safe per-session PID marker (`REMEMBER_DIR/tmp/deferred-<session id>.pid`); a dead marker (crash, kill) is treated as stale and replaced, and a different session id is never affected by another session's marker. `tests/test_resume_deferred_stacking_1060.py`'s own "still alive" test failed on windows-latest CI because its stand-in live process was started with a plain `subprocess.Popen`, which hands the guard a native Windows PID rather than the MSYS-space `$!` pid production always writes -- fixed by starting the stand-in through the resolved bash's own `&`/`$!`, which also let a disproven speculative `/proc/$pid` liveness probe be removed from `session-start-hook.sh`'s guard; plain `kill -0` was correct all along.
