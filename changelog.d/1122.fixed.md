- Fixed: `_lock_try_steal` (`scripts/lib-lock.sh`) re-reads the pid file it
  just renamed aside to tell apart "still the same stuck placeholder" (safe
  to steal) from "a faster contender's own write already recreated the pid
  file in the gap between this contender's own age check and its rename"
  (unsafe -- must hand back). #1119/#1120 (v0.45.1) made every read failure
  at this re-read report identically, whether a real timeout or a fast
  EACCES/EIO/cloud-sync refusal, so a fast-failing re-read of a genuine
  winner's brand-new pid was read exactly like a confirmed-still-stuck
  placeholder and fell through to the noclobber write below it, clobbering
  the winner's `save.lock`/`consolidation.lock`/`staging.lock` and
  producing two simultaneous holders -- the same class #1119/#1120 shipped
  as a non-blocking trap.d fragment one release earlier and then had to
  patch immediately as a regression. The re-read now also compares the
  renamed file's inode against what was captured just before the rename:
  a match is the same file whose first read already failed too, safe to
  steal; a mismatch, or either lookup coming back empty, hands back rather
  than guess -- `stat` needs no read permission on the file's content,
  unlike the re-read itself, so this works even when neither pid file is
  readable (#1122).
