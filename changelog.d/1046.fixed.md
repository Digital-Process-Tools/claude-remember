- Fixed #1046: SessionStart recovery could force-save another store's live session when several terminals in the same project directory each pinned a different `REMEMBER_DIR`. `_find_previous_transcript` only ever looked at mtimes, so a store starting up right after a sibling store had been active would pick up that sibling's newest transcript and force-save its summary into the wrong store's `now.md` / daily file. Recovery now declines to force-save a candidate that has no marker under this store's own `tmp/capture-alive.d/` roster (the same per-session marker `post-tool-hook.sh` already writes, and the #200 capture-gap check already reads) -- it may belong to a different store sharing this project's transcript directory. The guard sits at the recovery call site only, not inside `_find_previous_transcript` itself, so the #200 capture-gap check (which shares that function's result) is unaffected.
