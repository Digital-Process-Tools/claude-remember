- Fixed #1046: SessionStart recovery could force-save another store's live session when several terminals in the same project directory each pinned a different `REMEMBER_DIR`. `_find_previous_transcript` only ever looked at mtimes, so a store starting up right after a sibling store had been active would pick up that sibling's newest transcript and force-save its summary into the wrong store's `now.md` / daily file. Recovery now declines to force-save a candidate that has no marker under this store's own `tmp/capture-alive.d/` roster -- or the legacy single-slot file, the same two of `capture_was_seen()`'s three evidence sources that apply here (the third, a prior save, is already excluded by construction) -- it may belong to a different store sharing this project's transcript directory. The id itself is sanitized before the check, the same way `capture_was_seen()` already sanitizes it for its own roster lookup. The guard sits at the recovery call site only, not inside `_find_previous_transcript` itself, so the #200 capture-gap check (which shares that function's result) is unaffected.

  **Known trade-off, accepted by the issue's own design (self-review, not newly discovered after this landed):** a previous session that genuinely never ran under this store at all -- its hooks were never registered, so post-tool-hook.sh never wrote any marker for it -- can no longer be force-saved by recovery, because "no marker" is now indistinguishable from "may belong to a different store." This narrows recovery's original #200/#270 use case (rescuing a session whose hooks simply never fired) to only sessions this store has *some* independent evidence for. The worst case is a missed rescue, never a wrong one, which is the trade the issue explicitly asked for. One visible consequence: the capture-gap notice's "is being recovered" wording (`_recovery_attempted="true"`) can now only be reached when a marker already exists -- and a marked session is, by definition, not a capture gap at all (`capture_was_seen()`'s own first evidence source) -- so that wording is effectively dead code after this change. Left in place rather than removed, since deleting it is a separate decision from fixing #1046.
