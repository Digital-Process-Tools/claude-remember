- Fixed #1046: if you ran several Claude Code windows in the same project folder, each pinned to a different memory store, a window starting up could grab the WRONG window's unsaved conversation and force it into its own memory files. Recovery (the feature that rescues a conversation whose memory saving never ran) now checks that the conversation actually belongs to the store it is about to write into, and backs off if it cannot tell.

  The strictness of that check is itself new, so two things about it:

  - A session that never once registered a single tool call still has one piece of evidence for recovery to check: the moment it started. The other half-finished-gap warning (the one that tells you a previous session's saving never ran at all) still needs evidence that a tool actually ran, so it keeps working exactly as before -- this fix does not make it quieter or louder.
  - The very first time this runs on an existing install, there is a short one-time grace period: a conversation from just before the update, with none of this new evidence yet, is still rescued rather than silently given up on. After that one-time grace, the normal, stricter check applies. The cost of that grace: if you run several windows pinned to different stores in one project, each store's first start after the update can still save one other window's conversation into the wrong store, one last time. We chose that over silently losing an unsaved conversation from before the update; narrowing it further is tracked as a follow-up.
