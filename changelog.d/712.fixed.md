- Fixed: `bash -x scripts/session-start-hook.sh` no longer risks losing its
  stdout on Windows (round 2 of #690). `session-start-hook.sh` buffers its own
  stdout into a temp file via `exec 3>&1; exec > file`, then restores the real
  fd and `cat`s the buffer back at the end -- a mechanism the neighbouring
  bootstrap-dirs.sh trace tests never exercise. On `windows-latest`,
  `test_the_real_hook_traces_past_the_bootstrap` observed that exact command
  exit 0 with zero stdout bytes, with no Windows runner available to say which
  half of the fd-swap lost them. The buffer/fd-swap is now skipped entirely
  whenever an xtrace or `REMEMBER_TRACE=1` is active, the same way
  bootstrap-dirs.sh already stands its own fd 2 redirect down for a trace an
  operator deliberately started -- rather than debug the interaction blind,
  this removes it from the picture. The only visible cost is the plugin-promo
  banner, which already has to fall back the same way when the buffer's
  target directory is unwritable. The `xfail` on
  `test_the_real_hook_traces_past_the_bootstrap` stays in place, `strict=False`,
  until a real `windows-latest` run confirms the fix and flips it to XPASS
  (#712, #690).
