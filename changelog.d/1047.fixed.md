- Fixed #1047: `session-start-hook.sh`'s field extractor (`_stdin_json_string_into`) used `${var#*pattern}`, which is quadratic in bash -- O(n^2) on the raw payload's length. A host that pipes a whole transcript in as SessionStart's stdin (legal; the hook cannot refuse it) handed this function a multi-megabyte string: the reporter observed 27 `session-start-hook.sh` processes alive 21 hours each, immune to `SIGTERM` (a single builtin runs for hours with no signal check). First fixed by bounding the raw argument to the match itself (4096 bytes); a second round then found the hook's own line-accumulation join (`HOOK_STDIN="$HOOK_STDIN$_line"`) to be a SECOND, independent quadratic -- measured at 3.3 MB/2,500 lines: 68.8s on bash 3.2, 23.6s on bash 5.3, before extraction ever runs -- which the extractor-only bound could never reach, since it only ever saw one already-fully-accumulated string. Fixed by capping what is KEPT in `HOOK_STDIN` at a 32 KiB ceiling DURING accumulation (stop appending once the cap is reached, never build the full string and truncate afterwards), adopting the approach contributed in PR #1049 by CNSeniorious000 (Muspi Merol) -- credited via a `Co-authored-by` trailer on the commit. This supersedes PR #1049: that PR bounded each side of the join to a fixed 4 KB/4 KB (8 KB total), which would have silently truncated a legitimate payload between 8 KB and 32 KB before it ever reached the `before_session_start`/`after_session_start` listener-publish block (#266), breaking that block's own documented "file holds it, complete" contract for that range; this fix keeps the cap at 32 KiB, matching that block's own existing ceiling, so every payload at or under it still arrives byte-for-byte. The four fields this hook ever extracts (`cwd`, `session_id`, `transcript_path`, `source`) sit in the first few hundred bytes of every legitimate payload, so neither bound is a behavior change for real-world traffic. Out of scope: the three sibling hooks sharing the same operator (`post-tool-hook.sh`, `session-end-hook.sh`, `user-prompt-hook.sh`) and `capture-gap-check.sh`'s own copy (used against transcript file lines, not host stdin) -- noted in the issue's own comment thread as needing their own measurement, since a `PostToolUse` payload can legitimately carry a large tool result and a blanket 4 KB scan window there is a real behaviour question, not a drive-by.
