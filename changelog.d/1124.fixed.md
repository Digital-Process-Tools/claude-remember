- Fixed: three follow-on gaps in `_lock_try_steal` (`scripts/lib-lock.sh`)
  after #1122/#1123 (#1124). (1) The "before" inode snapshot was taken after
  BOTH the first pid read and the age check had already run -- a window wide
  enough for another contender to complete its own entire steal-and-rewrite
  cycle inside it, after which the snapshot answered for the WINNER's fresh
  pid file rather than for the original placeholder being judged, letting the
  #1122 check see a spurious match and clobber a live lock. The snapshot now
  runs before the first read even starts. (2) `_lock_file_inode` assumes
  rename preserves a file's identity; not true on FAT/exFAT under
  Cygwin/MSYS, SMB with noserverino, or FUSE without use_ino (#1103's own
  setup), where the identity check could never match for the same file and
  would hand back forever. A one-time self-test (`_lock_rename_preserves_identity`)
  now detects this and skips the comparison rather than trust metadata never
  confirmed meaningful on that filesystem. (3) Every hand-back `mv` of a
  claim file back into place could silently overwrite a pid another process
  had already written in the meantime; hand-back now reads the claim's own
  content back and writes it with `noclobber`, the same atomicity the real
  steal writes already use.
