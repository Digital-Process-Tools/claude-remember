- Fixed #1058: `write-handoff.sh` still misrouted a handoff when the Bash cwd had moved deeper than the subdirectory project a session actually started in. The #776 fix compared only two candidates ($(pwd) and the git toplevel) for the session-keyed hint; a directory strictly between the two -- reached only by a `cd` further down -- was invisible to it, and the write fell through to the enclosing repository's own store. Replaced the two-candidate check with a walk of every ancestor from $(pwd) up to the git toplevel. Independent review on PR #1081 found that picking the *nearest* ancestor with a hint could itself misroute after a `--resume` that re-published the hint at a different directory than the one it originally started in, so the walk now picks the *freshest* hint (by mtime) among every ancestor that carries one, with a positive control covering the single-hint case so this cannot degrade back to "only checks one candidate." The walk's own termination no longer depends on reaching the git toplevel at all -- it stops as soon as `dirname` makes no further progress, closing a reasoned (not observed; no MSYS environment available) infinite-loop risk on an MSYS/Windows UNC path. `scripts/doctor.sh`'s own project-dir resolver (added by #827, mirroring the pre-#1058 two-candidate shape) is ported to the same ancestor-walk logic so `/remember:doctor` reports the same store write-handoff.sh would actually write into.
