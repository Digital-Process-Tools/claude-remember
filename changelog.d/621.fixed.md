- Fixed: `log()` (`scripts/log.sh`) forked a `printf | tr` pipeline on every
  single call to flatten control bytes (#599), even though the large
  majority of log messages this codebase actually writes carry no control
  byte at all. `log()` runs on the per-tool-call hot path
  (`post-tool-hook.sh` logs at least once per invocation). A cheap in-shell
  pattern match now decides whether a message needs flattening before
  paying for the fork -- the fork itself, and its correctness (`LC_ALL=C`,
  same reasoning as #599), are unchanged for a message that actually
  contains one (#621). The pre-check tests literal byte values (an ANSI-C
  quoted range) rather than the POSIX `[[:cntrl:]]` bracket class: an
  earlier version of this fix used that class and it silently never
  matched a real embedded newline under Git Bash's MSYS2-built bash on
  windows-latest CI (deterministic, all 4 Python versions), while every
  Linux/macOS leg -- including this repo's own dev machine, on an old
  bash 3.2.57 -- stayed green. Caught before merge; the byte-range version
  needs no ctype/locale table lookup at all, so nothing is left for a
  different bash build to classify differently.
