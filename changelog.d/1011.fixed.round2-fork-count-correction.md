- Corrects a process-count claim from this range's own v0.43.0 entries (#1011, #1017) and fixes a real regression those entries did not catch: "1 (`tail` only)" / "a second spawn, `wc`" counted only **exec'd binaries** -- programs named on PATH -- never the bash **subshell forks** a `$(...)` command substitution or a `|` pipe also creates, even when nothing inside them execs a new binary at all. Counted the right way (total processes created, forks included -- the thing that matters on an affected Windows 11 25H2 build per #1011's own kernel-Token-leak report, where every one of those forks leaks a handle until reboot), `post-tool-hook.sh`'s below-threshold no-save path actually grew from 6 processes before #913/#1017 ever touched it to 9 after -- not shrank to "1" or "2" -- while the cooldown-active path's real reduction (8 to 5 on `/bin/bash` 3.2, 7 to 4 on bash 5) was genuine and is unaffected by this fix. The regression: `_pt_scan_lines` was called inside an outer `$(...)` command substitution (one subshell fork no exec ever showed up in), and its newline count ran the chunk through a `printf | wc -l` pipe (a second subshell fork for the pipe itself, on top of the `wc` exec `tests/spawn_counting.py`'s exec-only COUNTED list could already see). `_pt_scan_lines` now sets globals instead of being wrapped in a command substitution, and gets its newline count via a herestring into `wc -l` instead of a pipe -- removing both extra subshell forks without reintroducing #1017's quadratic per-byte newline scan (the `wc -l` call itself is unchanged, still a single linear C loop; what moved is only which processes carry the bytes to it). Measured with an interleaved tree-snapshot comparison against the `v0.42.4` tag (PID-delta, minimum of 9 runs, on both `/bin/bash` 3.2 and Homebrew bash 5): the below-threshold path now forks fewer processes than `v0.42.4` did, on both shells, with the cooldown path's own count unchanged by this fix either way. A new `tests/test_post_tool_total_processes_1011.py` pins the below-threshold path's total fork count via `strace -f -e trace=clone,fork,vfork` on Linux CI legs (skipped, not failed, wherever `strace` is unavailable -- macOS and Windows), with a positive control proving the method can see the cooldown path's own real reduction.
