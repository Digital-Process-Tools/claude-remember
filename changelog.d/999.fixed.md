- Fixed #999: three sibling test fixtures that write a `#!/bin/sh` shebang via `Path.write_text()` -- `tests/test_detect_tools_cache_668.py` (two sites), `tests/test_stdin_source_top_level_wins_344.py` and `tests/test_session_start_compact_recap_339.py` -- now write through a local `_write_shell_script` helper using `open(..., newline="\n")`, the same fix #994/#998 already applied elsewhere. `write_text()`'s default `newline=None` applies universal-newline translation on write, turning `\n` into `os.linesep` (`\r\n` on Windows) and corrupting the shebang line into a "bad interpreter" exec failure. `test_detect_tools_cache_668.py` carries no win32 skip marker, so this one was live on windows-latest CI; the other two are currently inert behind an existing win32 skip, same as #994's own file, but are fixed anyway so neither is a trap for whoever narrows that skip later. Each file gains a regression test pinning that its `_write_shell_script` helper never goes through `Path.write_text()`.
