- Fixed #1079: `capture-gap-check.sh`'s fast path (#1069) unconditionally re-sourced `log.sh` on every SessionStart, redoing `lib-memory-dir.sh`'s whole three-layer config merge (2-6 extra spawns, measured on macOS) and leaving its mktemp'd merged-config file in shared OS tmp -- a #362-style leak. It first loaded a scalar (`REMEMBER_RECOVERY_ENABLED`) from an env-cache FILE `session-start-hook.sh` publishes alongside the two scalars `post-tool-hook.sh`'s own fast path already replays; windows-latest CI showed that publish/load round trip through shared tmp is not reliable (the file sometimes was not yet visible to the child), falling the fast path through to the full merge on every run. Fixed properly: `capture-gap-check.sh` is only ever reached as a forked/backgrounded child of `session-start-hook.sh`'s own process, which already `export`s `REMEMBER_RECOVERY_ENABLED` before forking -- the child now uses that inherited value directly when present, no file involved, and falls back to the cache file (then the full merge) only for a direct/standalone invocation that has nothing to inherit. `tests/test_capture_gap_check_env_cache_1079.py` covers both the handoff-present and handoff-absent paths (the existing `tests/test_session_start_spawn_reduction_679.py` fast-path test was not edited; it only ever asserted `resolve-paths.sh` was skipped, which this fix does not change). Also fixes a race in `tests/test_capture_gap_notice.py`'s dedupe test, which only waited for the notice file and not the deferred phase's second write (the `capture-gap-reported` marker) before acting on it.
