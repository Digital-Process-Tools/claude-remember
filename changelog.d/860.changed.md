- #860: removed the plugin's own reads of the `REMEMBER_OAUTH_TOKEN` env var and the
  `haiku.oauth_token` config.json key for authenticating the nested `claude -p` summarizer call --
  on Claude Code, neither is read for that purpose any more. The plugin's `oauth_token`
  `userConfig` option (`/plugin` -> `remember` -> Configure, or `claude plugin config set remember
  oauth_token <token>`) is now the only recovery-token source there, declared in `plugin.json` with
  `sensitive: true` and delivered to the hook as `CLAUDE_PLUGIN_OPTION_OAUTH_TOKEN`. A still-set
  legacy value is detected by presence only, never its content, and reported once per save as a
  loud notice naming the source, surfaced by `/remember:doctor`. The host's own login
  (`CLAUDE_CODE_OAUTH_TOKEN`) keeps flowing through unchanged, so the default path with nothing
  configured is unaffected. Codex has no equivalent configure option, so its recovery path there is
  unchanged. README and the configuration reference were reworded in plain language to describe
  this without naming environment variables as a recipe. This clears the directory scan's "reads a
  credential from the user's machine" finding genuinely rather than by renaming or hiding what the
  code does; see `docs/releasing.md` for the full before/after and the grep sweep that backed it.
