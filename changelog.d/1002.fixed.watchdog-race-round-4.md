- Windows: #1002 round 4 -- PR #1010's own CI (run #38062128176, job #114242348418) found the 5s watchdog bound shipped in round 3 was tuned on a 5-run sample (max 0.422s) that did not hold under a loaded runner: a sibling healthy call took 5.13s and this run's own call took 6.03s, tripping the watchdog and killing a real `wscript.exe` launch (`RC=137`), turning a Windows CI leg red on `main`. The bound is now 15s. More importantly, a watchdog kill is no longer risky on its own: `scripts/post-tool-hook.sh`'s nohup fallback now checks whether `lib-detach-pidwrap.sh` already claimed `PID_FILE` and is still alive before launching a second, independent save (closing a double-save race the watchdog's own kill could otherwise trigger -- `WshShell.Run` detaches the real command from `wscript.exe`'s own process, so killing `wscript.exe` does not stop it), and `scripts/lib-detach.sh`'s "hidden route unusable" cache no longer treats a watchdog kill (`RC=137`) the same as a structural failure, so one slow call no longer forces every save for the next hour onto the slower fallback.
